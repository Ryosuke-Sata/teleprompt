# ことば — 日本語テレプロンプター

原稿の読みの長さに合わせて進む、ブラウザ内で動作する日本語テレプロンプターです。TypeScript + Viteで構築し、GitHub Pagesへ静的ファイルとして公開できます。原稿を解析APIへ送信しません。

## アプリとして追加

公開ページを開き、初回の案内またはページ下部の「アプリに追加」を選びます。案内を「あとで」で閉じても、ページ下部からいつでも開けます。

- Windowsやその他のPCでは、ChromeまたはEdgeの案内に沿ってインストールします。
- macOS Sonoma 14以降のSafariでは、「ファイル」→「Dockに追加」を選びます。
- Androidでは、Chromeの「ホーム画面に追加」からインストールします。
- iPhone・iPadでは、共有メニューの「ホーム画面に追加」を選び、「ウェブアプリとして開く」が表示されたらオンにします。

追加後は、端末のホーム画面やアプリ一覧から「ことば」を開けます。ブラウザ版の原稿が追加後のアプリに表示されない場合は、ブラウザ版でJSONを保存し、追加後のアプリで読み込んでください。

## ローカルで起動

Node.js 24 LTSを推奨します（22.12以上）。PowerShellなどでプロジェクトのフォルダーを開き、実行してください。

```powershell
npm ci
npm run dev
```

ターミナルに表示されたLocal URLをブラウザで開きます。通常は `http://127.0.0.1:5173/` です。停止はターミナルでCtrl+C。

```powershell
npm test
npm run build
npm run preview
```

`build`は辞書・ライセンスの準備、型チェック、本番ビルドを行います。`preview`の通常のURLは `http://127.0.0.1:4173/` です。HTMLを直接ダブルクリックする方法には対応しません。Web Workerと辞書をHTTPで読み込む必要があります。

## 使い方

1. 「原稿」でタイトルと本文を編集します。空行が段落の区切りです。
2. 「設定」で読む速さ、文字サイズ、行間、本文幅、色、開始前カウントダウンを調整します。
3. 読みの解析完了後に再生します。日本語補正モードは拍/分、一定速度モードはpx/秒で調整できます。
4. 人名・専門語は「読み・辞書」で確認します。本文で文字を選び、この箇所だけの読みを指定できます。ユーザー辞書の登録は別原稿でも再利用します。優先順位は「箇所の指定 → ユーザー辞書の最長一致 → 自動解析 → 読み不明時の推定」です。
5. 読み直すときは前後の段落へ移動します。本文のカーソル位置に名前付きブックマークも登録できます。

編集対象の位置がずれる誤りを避けるため、本文の編集時には箇所ごとの読み修正・ブックマークをリセットして通知します。ユーザー辞書は維持します。原稿を整えてから細かな読みを指定する使い方を推奨します。

### カウントダウン・メモ・間

開始前のカウントダウンは、なし・3秒・5秒から選びます。カウントダウン中の再生ボタンは中止ボタンになります。一時停止からの再開時はカウントダウンを省きます。

以下の指示を専用の行に記入します。本文の下にあるボタンでも挿入できます。

```text
ここは読み上げる本文です。

[[メモ:肩の力を抜いて、カメラを見る]]
[[待機:2]]

2秒待ってから、続きへ進みます。

[[停止]]

再生ボタンを押すまで、ここへ進みません。
```

メモは表示しますが読み時間に加算しません。待機は0〜60秒。手動停止で待つ時間は推定所要時間に含まれません。指示の書式が不正な場合はエラーを示し、修正するまで再生しません。

### リハーサル

「自分の速さを見つける」で計測を開始し、サンプル文章を自然な速度で読んだ後、計測を終了します。推奨速度を確認し、「この速さを使う」で適用します。録音・マイク権限は使いません。

計測には話者の間も含まれるため、適用時は句読点・段落の追加の間を0秒にします。必要なら設定から追加できます。5秒未満、または60〜1200拍/分の範囲外の計測は適用できません。自動計算は目安です。

### 保存と読み込み

- **JSON（`.teleprompt.json`）**: 原稿・設定・ユーザー辞書・読み修正・ブックマークをまとめて保存します。JSONの読み込みは辞書を含めてファイルの内容へ置き換えます。現在の内容は先に保存してください。アプリ専用の構造で、他社製品との互換性は保証しません。
- **TXT（`.txt`）**: 原稿のみ。UTF-8（BOMあり・なし）、LF/CRLF/CRの改行に対応します。読み込み時は設定とユーザー辞書を維持し、読み修正とブックマークをリセットします。
- ファイルは2MB以下、本文は10万UTF-16コード単位（画面の文字数と同じ）、辞書500語、読み修正1000件、ブックマーク500件までです。
- 自動保存は現在のブラウザに限ります。ブラウザのデータ削除、プライベートモード、容量不足で保存できない場合があります。バックアップはJSONを使ってください。
- インポート後は先頭で停止します。不正ファイルの場合は編集中の内容を置き換えません。

### 操作

| キー | 操作 |
| --- | --- |
| Space | 再生・一時停止 |
| ← / → | 前の段落 / 次の段落 |
| Home | 先頭に戻る |

入力欄・ボタン・ダイアログ・日本語変換中はグローバルショートカットを抑止します。ボタンへフォーカスがある場合は、そのボタン本来のキーボード操作を優先します。タブを非表示にすると再生を一時停止します。表示設定・原稿の変更や画面サイズの変更でも一時停止します。

## GitHub Pagesへ公開

GitHubへのpushと実際の公開設定は利用者が行います。Codexはリポジトリ作成・commit・push・公開を行っていません。

1. GitHubにリポジトリを作成し、このフォルダーのソースをmainブランチへpushします。`node_modules`、`dist`、生成される辞書ファイルは不要です。`package-lock.json`は含めてください。
2. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定します。
3. **Actions → Deploy to GitHub Pages → Run workflow** を実行します。以後、mainへのpushで自動デプロイします。
4. ワークフローが成功したら、デプロイ結果に表示された公開URLを開きます。

`.github/workflows/deploy.yml`に、依存導入 → テスト → 型チェック・ビルド → Pages用成果物のアップロード → 公開を定義しています。PRではテスト・ビルドのみ行います。Pagesを利用できるリポジトリ種別・アカウントが必要です。公開する原稿をソースへ含めないようにしてください。

`base: './'`を使っているため、`https://ユーザー名.github.io/リポジトリ名/`でも利用できます。独自ドメインは初版で自動設定しません。公開サイトは原稿の共有機能を持たず、各利用者が自分のブラウザへ入力します。

## 日本語の時間配分

kuromoji.js / IPADICの発音・読みから拍（モーラ）を近似します。小さい「ゃ・ゅ・ょ」などは前の仮名と合わせ、「っ・ん・ー」はそれぞれ1拍と数えます。表示行ごとに読み時間を配分し、行をまたぐ語の拍数は表示文字数に比例して分配します。文章全体を平均した固定速度にはしません。

数字、助数詞、人名、英語、専門語などの読みや自然な発話時間を完全に推定するものではありません。黄色で表示される読み不明箇所は時間を推定します。読みが取得できても誤読の場合があるため、本番前に確認してください。

## 配布物とライセンス

- kuromoji.js 0.1.2: Apache-2.0。
- 同梱IPADIC: NAIST / ICOTの著作権表示・条件・免責文を保持します。
- `npm run prepare:vendor`が公開用辞書とLICENSE/NOTICE、関連依存ライセンスを準備します。本番ビルドにも含みます。アプリのフッターから参照できます。
- HTTPのContent-Encodingで辞書が解凍済みになる環境に対応するため、生成するブラウザ用kuromojiにgzipシグネチャの確認処理を加えています。元の告知を保持し、変更箇所の告知を生成ファイルへ記載しています。
- 原稿・設定は外部へ送信しません。ページと辞書の初回取得には通信が必要です。オフラインキャッシュ、音声認識、左右反転、録画、クラウド同期は初版の対象外です。
